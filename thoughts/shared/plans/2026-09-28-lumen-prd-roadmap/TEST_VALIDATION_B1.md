## Findings

1. **Important — concurrency-cap assertion is vacuous.** `test/link-check.test.mjs:124-147` builds a 2-URL fixture (`:128`), so `runCheck` spawns `Math.min(CONCURRENCY, 2)` = 2 workers and `expect(peak).toBeLessThanOrEqual(5)` (`:146`) passes for *any* cap ≥ 2 — and for an unbounded `Promise.all` implementation too. The I5 "bounded concurrency 5" invariant is unobserved. Fix: fixture with > 5 URLs, assert `peak <= 5` (optionally `peak >= 2` to prove parallelism).
2. **Important — the checker's failure contract (what CI keys on) is untested.** `runCheck`'s non-`--json` log lines and the `process.exit(failures ? 1 : 0)` main block (`scripts/ci/link-check.mjs:122-138`) are never exercised: the test at `test/link-check.test.mjs:129-147` asserts only the return value. A regression to always-exit-0 (or dropping the FAIL/source lines) keeps every gate green. The return-shape oracle (url/status/sources) is real, but the exit code is the actual scheduled-workflow signal per I5 "fails honestly". Needs an exported `main({log, exit})` seam or equivalent.
3. **Nit — contract-counts loudness is per-file, not per-sentence; one test is currently decorative.** `test/contract-counts.test.mjs:41-49` collects hits across 4 patterns and the README/rules-reference tests only require `hits.length > 0` per file — rewording ONE of README's two count sentences ("the 20 rules" → "all twenty rules") escapes the gate while the other sentence keeps it green, so the header claim "a count pattern that stops matching … fails loudly" holds only when all sentences in a file lose coverage. Also `test/contract-counts.test.mjs:87-91` (packages/cli/README.md) has no `hits.length > 0` guard and that file currently contains zero count sentences — it asserts nothing today.
4. **Nit — value-pairing oracle misses unquoted values.** `onboard.test.ts:53` requires a quoted value (`KEY["']?\s*[:=]\s*["']…`), so a payload like `LUMEN_PSI_KEY=your-key` or `LUMEN_PSI_KEY: abc` would pass. This faithfully implements the plan's pinned regex, so it's a heuristic-scope note, not a deviation.
5. **Nit — extraction honesty: fixtures are a superset of real shapes, with two caveats.** Verified against the real repo: the extractor's 18 collected URLs exactly match a manual grep of README/SECURITY/packages/*/README/locked-names (badges with query strings, SECURITY.md `<…>` autolink, and markdown links all captured; no real URL is mis-extracted). Caveats: (a) the fixture comments at `test/link-check.test.mjs:47,49` say `>`/`)` are "stripped", but the prose regex `[^\s<>()"']+` never admits those characters — char-class exclusion does the work and `stripTrailing`'s `>`/`)` branches are reachable only via JSON string values; (b) URLs *inside* locked-names snippet strings (releases URL in `mcpbInstall`, example.com in `npxAudit`) are not collected — the JSON walk only takes values that *start* with http(s) (`scripts/ci/link-check.mjs:51-59`). Both URLs are covered today from other files, but a new URL appearing only inside a snippet would silently escape the "every absolute URL the published materials expose" claim. The 10 s per-attempt timeout (`AbortSignal.timeout`) is likewise unobserved (asserting `init.signal` would cover it).
