## Overview

`lumen history` (13th command: audit|rank trends with --since, prune via maxGenerations), `audit --format html` (one self-contained report file), a monitoring recipe, `@lumen-seo/audit/testing` published + a plugin guide + the optional plugin-render package, Worker bearer auth + origin allowlist, and the P1/P2 hygiene rows.

## What We're NOT Doing

- No daemon/monitoring service (a documented cron RECIPE only).
- No changesets adoption (recorded decision: defer — owner workflow choice).

- No Durable-Objects pacer (P3 "only if real traffic").

## Phase 1: history command + prune + html report

- `cmd/history.ts`: `lumen history <audit|rank> [--domain] [--since ISO] [--limit N] [--format json|csv] [--json]` — reads via d.history.list, filters since client-side, renders (reuses rank.ts's CSV conventions incl. formula-neutralization); `lumen history prune [--keep N]` trims rotated generations through the store's optional prune.
- `rank --history` stays; prints a one-line deprecation note pointing at `lumen history`.
- HistoryStore port += `prune?(o: { kind?: HistoryKind; keepGenerations?: number }): Promise<number>` (optional, additive); JsonlHistoryStore implements multi-generation rotation `.1..(.N-1)` honoring `history.maxGenerations` (default 2) + prune deletes beyond keep; core config += `history.maxGenerations` (int ≥1, default 2 — 4 registration sites).
- `render/html.ts`: `renderHtml(report)` — one file: inline `<style>`, header (site/score/pages/dates/incomplete), by-rule groups with fixHint/helpUrl/provenance lines, per-page table, attributions footer (CC BY 4.0 etc. from locked attributions), "generated by lumen vX — provenance per finding" note. No external requests, no scripts. `--format html` joins audit FORMATS (--out writes it; stdout silent with --out per the sarif/md contract).
- Contracts: COMMAND_NAMES 13, help entries, locked-names (cliCommands `history`, cliFlags `--since`), cli-reference, no-telemetry `['history','audit']` case (fixture store), snapshots.

## Phase 3: E2.5 gateway hardening

- Worker: `WORKER_AUTH_TOKEN` — when set, `/mcp` (and REST data routes) require `Authorization: Bearer <token>`; missing/wrong → 401 JSON-RPC error (typed, no timing leak: constant-time compare via crypto.subtle). Unset = today's behavior (documented self-deploy/personal).
- CORS: `WORKER_ALLOWED_ORIGINS` (comma list) — when set, reflect ONLY those origins (Vary: Origin); unset keeps `*`. Worker tests: auth on/off × origin allow/reflected.
- Docs: mcp-onboarding page gains the two env vars + the "self-deploy, personal use" note (already present per research — extend).
