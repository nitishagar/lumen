# IMPLICIT SPEC — seolite surfaces

Requirements only. Mechanisms live in PLAN.md. Global invariants I1–I17 (research Implicit Spec section) are inherited verbatim; this file states (1) what each one obligates on the CLI/MCP/storage surface, (2) aspect-local edge requirements E1–E15, (3) bounding assumptions B1–B21 that make the plan autonomous (zero open questions).

## 1. Global invariants — obligations on this aspect

| # | Invariant | Obligation on surfaces |
|---|---|---|
| I1 | Zero-cost defaults | Every CLI command and MCP tool default path uses self-fetching or free/BYOK providers only. BYOK env values are read at call time (never at boot, never persisted). BYOK absent → provider is skipped with an explicit "not configured" result field — never a crash, never a keyless call to a key-required endpoint (CrUX). Over HTTP, keys arrive per-request via headers and are passed through only. |
| I2 | Pluggability at every data boundary | CLI/MCP surface is invariant under provider swap: tools/commands consume SPI interfaces injected by a composition root; zero vendor calls outside providers. Unknown provider name in config → explicit error listing available providers → exit code 2. |
| I3 | Data honesty | Every metric in every output (human terminal, `--json`, MCP tool result, REST response) carries provenance (provider + kind + retrievedAt). Heuristic/gray values carry estimate labels. Provider failure → field omitted or marked `unavailable` with reason — never zero-filled. |
| I4 | Crawl etiquette | Surfaces pass crawl budgets/limits through to the audit engine; the CLI exposes bounded flags (`--max-pages`), never unbounded crawls. UA/rate limiting is owned by core Fetcher + audit engine. |
| I5 | MCP-first parity | All five locked tools exist on BOTH stdio and remote HTTP from ONE `buildMcpServer` factory (identical tool set); CLI covers the same capabilities plus the onboarding printout. REST is an explicit subset (page-report, keyword-ideas). Tool descriptions are agent-oriented, high-signal, with `response_format` concise/detailed. |
| I6 | Worker stays thin | The Worker never fetches or parses target URLs, never imports cheerio or the audit engine, holds no session/KV/DO state, and rejects requests that would exceed budget up-front (typed errors), including response-body caps on upstream reads. |
| I7 | Look derived, not copied | (Site aspect.) Surfaces contribute no UI except terminal/help text; no pi.dev assets or copy anywhere in CLI/MCP strings. |
| I8 | License & attribution | Attribution metadata supplied by providers is surfaced in tool/command outputs wherever the underlying data is displayed (CrUX CC BY 4.0, Tranco, Open PageRank). |
| I9 | TDD gate | Every behavior and every edge below has a deterministic test before merge; no live network in tests (fixture providers only); suite green = phase done. |
| I10 | Determinism | Identical inputs → identical outputs: no wall-clock dependence in outputs except values explicitly labeled as retrieval timestamps sourced from injected clock; history rotation is size-triggered (not time-triggered) and deterministic. |
| I11 | Repo hygiene | Apache-2.0; commits by Nitish Agarwal, no AI trailers; packages publish-ready (bin, files, exports) though publishing happens in M2. |
| I12 | SSRF safety | Every user-supplied URL (CLI args, tool `url` params, REST `?url=`) is validated — composing core's exported `isBlockedTarget` predicate (scaffold-core `ssrf.ts`) with an http/https scheme whitelist — before the value reaches any fetch or is echoed: private/loopback/link-local/ULA ranges refused. The Worker validates even though it does not fetch targets (defense in depth + PSI/CrUX receive the URL as a parameter). |
| I13 | Output safety | Crawled data echoed to the terminal is ANSI/C0–C1-sanitized and length-capped; JSON outputs use JSON encoding; history dirnames derived from domains are path-safe (ASCII/punycode + slug + content hash); `--out` writes are atomic; crawled content never executes as markup anywhere we emit it. |
| I14 | Concurrency, cancellation, partial failure | Global concurrency cap and per-request timeouts owned by engine/Fetcher and passed the caller's AbortSignal; SIGINT stops promptly; an interrupted audit's report is labeled `incomplete: true` and written atomically or not at all; re-runs never duplicate history side effects (append happens only after a successful provider result). |
| I15 | Boundary inputs | Defined behavior for: non-http(s) URL args, malformed URLs, empty/overlong seeds and keywords, IDN/unicode domains (normalized via domainToASCII), unknown config keys, unknown flags/commands, oversized upstream payloads — each maps to a typed error and exit code 2 (CLI) or typed error result (MCP/REST). |
| I16 | Privacy / no telemetry | No telemetry anywhere. The set of outbound requests is enumerable in tests (recording Fetcher + Miniflare outbound recorder + lint ban on direct `fetch` outside core). BYOK header values and env values never appear in logs, errors, history, or `config show`. Docs-worthy statement: only user-initiated provider queries leave the machine. |
| I17 | Retry & backoff | Owned by core Fetcher; surfaces map typed provider failures (provider name attached) to exit 2 (CLI) / typed error results (MCP) with actionable messages; upstream 429/Retry-After surfaces as a typed rate-limit error. |

## 2. Locked interface facts (from ARCHITECTURE.md — non-negotiable, cite-only)

- Package names/paths: `packages/cli` → `@seolite/cli` (bin `seolite`), `packages/mcp` → `@seolite/mcp` (with `worker/` inside).
- CLI command names: `audit <url> [--max-pages N] [--out report.json]`, `report <url>`, `keywords <seed>`, `rank <keyword> --domain <domain>`, `authority <domain>`, `mcp`, `config show`. `--json` on every command.
- Exit codes: 0 ok / under threshold; 1 issues at/above `failThreshold`; 2 config/provider error.
- MCP tools (names locked): `seolite_audit_site`, `seolite_page_report`, `seolite_keyword_ideas`, `seolite_rank_check`, `seolite_authority`; optional `response_format` concise|detailed (default concise); over remote HTTP `seolite_audit_site` returns a typed local-only error pointing to `npx @seolite/cli`.
- MCP stack: `@modelcontextprotocol/sdk` `McpServer`; local `StdioServerTransport` via `seolite mcp`; remote via Cloudflare `createMcpHandler` stateless pattern (deprecated `McpAgent` is forbidden).
- REST routes (locked): `POST /mcp`, `GET /api/v1/page-report?url=` (PSI/CrUX-derived only — Worker never fetches/parses the target), `GET /api/v1/keyword-ideas?q=`, `GET /healthz`. BYOK per-request headers (`x-seolite-psi-key`, `x-seolite-crux-key`, `x-seolite-opr-key`), never logged or stored.
- HistoryStore lives in core (M0) as the locked `interface HistoryStore { append(e): Promise<void>; list(q?: {keyword?;domain?;limit?}): Promise<RankHistoryEntry[]> }` with `RankHistoryEntry{keyword, domain, position: number|null, provider, url?, retrievedAt}` (scaffold-core SC-15); the JSONL implementation lives in `packages/cli` and MUST implement that interface exactly; storage under `.seolite/` with path-safe domain dirnames (I13); rank history is append-only; the rotated generation file is literally `history.1.jsonl`.
- Workers tests via `@cloudflare/vitest-plugin` (Vitest ≥ 4.1, Miniflare, fully local). Vitest everywhere. Node ≥ 22, ESM-only, npm workspaces.
- Worker must never parse HTML (cheerio is Node-side only): the Worker composition consumes the providers aspect's locked `createWorkerSafeProviders(config, deps)` factory via the single barrel export `@seolite/providers` (R7; providers TC-REG-5 guarantees the worker-safe factory does not load cheerio — `ddg-serp` is the only cheerio consumer and is absent from the Worker). Surfaces additionally guards with its own bundle-scan test.
- RECONCILIATION.md (R1–R10) is authoritative where cited: closed severity vocabulary `error|warning|info` (R1); `failThreshold` default `"error"`, `off` disables the gate (R2); crawl budgets core-owned — `maxPages` 100 (clamp 10k), `maxDepth` 5, `maxDurationMs` 300_000 (R3); MCP tools carry NO `maxPages` default — core config default applies (R8); history root/rotate/dirname scheme (R9); Worker safety via `createWorkerSafeProviders` (R7).

## 3. Aspect edges (surfaces-local requirements)

- **E1 Exit-code contract.** 0 = command succeeded and (audit only) no issue at/above `failThreshold`. 1 = audit executed but gate failed: any issue severity ≥ `failThreshold`, OR report `incomplete: true` (an untrustworthy report must not pass a CI gate). 2 = config/provider/usage error (unknown command/flag, invalid URL, unknown provider name, config validation failure, typed provider failure, typed robots refusal, cancellation via SIGINT, unhandled internal error). No other exit codes are ever emitted. Severity vocabulary is the closed R1 set `error|warning|info`; `failThreshold` comes from config (core loader) overridable per-run by `--fail-threshold <info|warning|error|off>`, default `"error"` (R2); `off` disables the severity comparison entirely (never gates) — but `incomplete: true` still gates regardless of threshold. Consumed by `audit` only. The CLI flag enum and the MCP tools' `failThreshold` enum are the identical 4-value set `info|warning|error|off` (I5 parity).
- **E2 `--json` contract.** Every command accepts `--json`; JSON mode prints exactly one UTF-8 JSON document to stdout (no banners, no decoration, trailing newline). Diagnostics and progress go to stderr only. Human mode is the default and never interleaves with JSON. `seolite mcp` stdout carries JSON-RPC protocol only — any startup note goes to stderr.
- **E3 Terminal output encoding (I13).** Crawled strings (titles, snippets, URLs, evidence) rendered in human mode are stripped of ANSI CSI/OSC and all C0/C1 control characters, and length-capped. History dirnames are `slug-<sha256:8>` of the ASCII-normalized domain (deterministic, collision-free, path-safe). `--out` report writes are atomic (temp file + rename in the same directory).
- **E4 History contract.** Location `./.seolite/history/rank/<slug>-<hash8>/history.jsonl` (R9; `SEOLITE_HISTORY_DIR` overrides for tests/users). Each line is exactly core's `RankHistoryEntry{keyword, domain, position: number|null, provider, url?, retrievedAt}` — no extra stored fields (`found` is derived as `position !== null` in command output, never persisted). `JsonlHistoryStore implements HistoryStore` — core's locked `{append, list}` methods (SC-15). Append-only; rotation size-triggered (default 1 MiB): the current file is renamed to the literal `history.1.jsonl` (oldest rotated generation overwritten), deterministic. `list(q?)` reads `history.1.jsonl` then `history.jsonl`, newest-last, tolerating and skipping a truncated/malformed final line (crash safety). `rank` appends by default; `--no-save` opts out. History is local-only — it is never sent anywhere (I16) and never written by the Worker.
- **E5 BYOK handling.** Config stores env var NAMES (architecture contract); values are resolved from `process.env` inside command/tool execution, at call time. Default env names: `SEOLITE_PSI_KEY`, `SEOLITE_CRUX_KEY`, `SEOLITE_OPR_KEY` (config may point at other names). `config show` prints names + `set: boolean` only — never values. Over HTTP, keys come from request headers, are forwarded to the matching provider call, and are never logged, stored, cached, or echoed in any response.
- **E6 Transport parity with typed local-only.** `buildMcpServer(deps)` registers all five tools regardless of transport. A capability absent from the injected deps (audit runner, SERP provider, page-meta fetcher) yields a tool that is still listed (identical tool set, I5) but returns a typed error result: `code: "LOCAL_ONLY_CAPABILITY"` with a message naming `npx @seolite/cli <command>`. Locked v1 capability map: over HTTP `audit_site` and `rank_check` are local-only (v1's only SERP provider, `ddg-serp`, is cheerio-based → no Worker-safe SERP provider exists); `page_report` serves PSI/CrUX only (no target meta fetch); `keyword_ideas` and `authority` serve from `createWorkerSafeProviders(config, deps)` (R7) with the Worker config selecting `google-suggest`, `wikipedia-demand`, `pagespeed`, `crux`, `openpagerank` (tranco deliberately unselected on the Worker: bulk-CSV stream parsing cannot fit the 10 ms CPU ceiling, I6). Tool descriptions state the transport-dependent capability.
- **E7 Tool inputSchema contract.** Wire `inputSchema` is JSON Schema (2020-12, per MCP spec). Guaranteed and asserted on the wire (`tools/list`): `type: "object"`, `required` exactly the fields without defaults, enum-constrained fields, integer min/max bounds, property names/types. `additionalProperties: false` and schema-level defaults are asserted opportunistically and snapshot-documented per installed SDK (B7): if the SDK's Zod raw-shape path does not emit them, the wire assertion downgrades to the guaranteed set — strict rejection of unknown/extra args is guaranteed regardless, enforced handler-side by a shared `strictArgs` guard wrapped around all five handlers (CLI and MCP stay behaviorally identical). All five tools accept `response_format: "concise"|"detailed"` (default `concise`).
- **E8 Tool output-shape contract (concise).** Locked concise shapes: `audit_site` → `{url, pages, score, countsBySeverity, topIssues[≤10], passesThreshold, incomplete, failThreshold}`; `page_report` → `{url, lab?, field?, meta?|unavailable, attribution[], limitations[]}`; `keyword_ideas` → `{seed, ideas[{term, source{provider,kind}, estimateLabel?, demand?}], attribution[]}`; `rank_check` → `{keyword, domain, found, position|null, matchedUrl?, provider, retrievedAt}`; `authority` → `{domain, signals[{provider, kind, value, attribution, retrievedAt}], unconfigured[]}`. Detailed mode adds per-page issues / full SERP results / full provenance. Provenance wrapper `{value, source{provider, kind}, retrievedAt}` on every metric (I3).
- **E9 REST subset contract.** `GET /healthz` → `{"ok":true}`. `GET /api/v1/page-report?url=&strategy=` returns PSI/CrUX-derived fields only; the target URL is validated (I12) but never fetched or parsed by the Worker. `GET /api/v1/keyword-ideas?q=&limit=&lang=`. All errors use a single typed JSON envelope `{error: {code, message, provider?}}` with codes including `INVALID_URL`, `MISSING_PARAM`, `LOCAL_ONLY_CAPABILITY`, `PROVIDER_UNCONFIGURED`, `UPSTREAM_FAILED`, `PAYLOAD_TOO_LARGE`, `NOT_FOUND`, `METHOD_NOT_ALLOWED`. Permissive CORS on `/mcp` + `/api/v1` (Streamable HTTP browser clients), including the `x-seolite-*` header names.
- **E10 Worker budget contract (I6).** Self-imposed bundle cap 1.5 MB gzip (platform hard limit 3 MB), enforced by a check script. No KV, no DO, no sessions; per-request composition (fresh provider instances per request). Upstream response-body cap (default 2.5 MB) enforced by a capping Fetcher wrapper: Content-Length pre-check + streaming abort. Env kill-switch `WORKER_ENABLE_PSI` (default `"true"`) documented for deploy-time CPU safety.
- **E11 Onboarding payload contract.** `seolite mcp --print <json|claude|cursor|vscode>` prints the matching onboarding payload and exits 0 without starting the server: universal `mcpServers` JSON snippet; `claude mcp add --transport stdio seolite -- npx -y @seolite/cli mcp` one-liner; Cursor deep link (`cursor://anysphere.cursor-deeplink/mcp/install?name=seolite&config=<base64>`); VS Code deep link (`vscode:mcp/install?<uri-encoded json>`). `--url <remote>` switches all four to remote-HTTP variants. Payloads are deterministic strings (snapshot-tested) and never embed key material.
- **E12 No-telemetry testability (I16).** All outbound HTTP flows through the injected core Fetcher; tests enumerate every outbound call (Node: recording Fetcher + global `fetch` stubbed to throw; Worker: Miniflare outbound recorder with a host allowlist). Lint bans direct `fetch` outside the core Fetcher module. The Worker performs no logging of request/key material. A test asserts env key values never appear in any stdout (sentinel-key grep).
- **E13 Concurrency contract.** Worker: stateless — each request builds its own server + provider instances; concurrent requests share nothing mutable. stdio: the SDK may interleave tool calls; handlers are pure functions of (args, deps) and the history store serializes appends through an in-process promise queue; cross-process appends rely on single-write `O_APPEND` semantics for small lines. No module-level mutable singletons after composition.
- **E14 Cancellation/partial-failure contract.** Tool handlers receive the SDK request signal and pass it into the audit runner; CLI wires SIGINT → AbortController. On cancellation, audit assembles the partial report labeled `incomplete: true` (atomic `--out` write), history appends happen only after a successful provider result, and the process exits 2 with a `cancelled` message. The long-running `seolite mcp` serve command must also shut down for real: its wait promise resolves on stdin close (graceful → exit 0), transport `onclose`, or the run() AbortController (SIGINT → exit 2) — Ctrl-C must never hang the process.
- **E15 Help & bare-invocation contract.** Bare `seolite` (no args), `seolite --help`/`-h`, and `seolite <command> --help`/`-h` print usage (global or per-command) to stdout and exit 0 — the help intercept runs BEFORE strict `parseArgs` validation, so help is never a usage error. Help is not part of the locked command set (no `help` subcommand is added). Unknown commands/flags remain exit 2 with a usage hint. Help text is deterministic and snapshot-tested.

## 4. Bounding assumptions (autonomous-mode defaults; no open questions)

- **B1** CLI is args-only: hand-rolled dispatch over Node 22 built-in `node:util` `parseArgs` (strict mode). Chosen deliberately; no CLI framework dependency. Help/usage text is hand-written.
- **B2** MCP tool results are JSON-in-text content (`{type:"text", text: JSON.stringify(result)}`); `outputSchema`/`structuredContent` adoption is deferred (tool names/schemas are stable, so it is a compatible later addition).
- **B3** Default `failThreshold` = `"error"` per R2 (only error-severity issues gate out of the box; `off` disables the gate; opting into `warning` is explicit via config/flag). `critical` does not exist in the vocabulary (R1). Consumed by `audit` only; `report`/`keywords`/`rank`/`authority` exit 0 on success.
- **B4** History rotation defaults: 1 MiB per file, single rotated generation (`.1.jsonl`).
- **B5** Domain dirname = slugified `domainToASCII(domain)` (non `[a-z0-9.-]` → `-`, capped 80 chars) + `"-"` + first 8 hex of sha256(normalized domain), always appended (deterministic, collision-free).
- **B6** Cross-process concurrent history appends rely on `O_APPEND` single-write atomicity for small lines (records are kept small by schema bounds); no file locking in v1.
- **B7** Tool registration uses `McpServer.registerTool` with Zod raw shapes (Zod shared with the SDK's own dependency); schema truth is asserted on the wire (`tools/list` golden/structural tests), not via a Zod→JSON Schema export API. Fallback (locked): if the installed SDK's raw-shape path does not emit `additionalProperties: false` or defaults on the wire, the wire contract downgrades to the guaranteed set (E7) and unknown-param rejection is enforced handler-side by the shared `strictArgs` guard — CLI and MCP remain behaviorally identical either way.
- **B8** MCP TypeScript SDK ≥ 1.11 assumed (`registerTool`, request `signal` in handler extra). `createMcpHandler` is called with a per-request-built `McpServer` instance inside the Worker `fetch` (documented stateless wrapping pattern; per-request construction is what makes it stateless and lets request headers reach the composition).
- **B9** Worker is authless (no OAuth) in v1; no rate limiting beyond Cloudflare platform defaults; CORS is permissive on `/mcp` + `/api/v1`.
- **B10** `WORKER_ENABLE_PSI` defaults to `"true"` with the 2.5 MB capping Fetcher guard; residual risk of Workers 1102 CPU errors from large PSI JSON is accepted and mitigated by the kill-switch + measured at deploy time (M2).
- **B11** `rank` with the domain not found in the top N is a successful result (`found:false`, `position:null`, exit 0).
- **B12** Config path resolution: `./seolite.config.json` in cwd, `--config <path>` flag, `SEOLITE_CONFIG` env override (used by tests).
- **B13** History root defaults to `./.seolite/history`; `SEOLITE_HISTORY_DIR` overrides it (tests/users).
- **B14** Crawl budgets are core-owned per R3 (`maxPages` 100 clamp 10k, `maxDepth` 5, `maxDurationMs` 300_000, `maxConcurrency` 5, fetch `timeoutMs` 10_000, `retries` 2); surfaces only plumbs `--max-pages` (no flag-level default — R8) and the tool `maxPages` arg (optional, no default — R8) onto them.
- **B15** Deep-link vendor parameter shapes follow the research snapshot (Cursor: base64 `config` param; VS Code: URI-encoded JSON query; no `claude://` desktop deep link exists); re-verified against vendor docs current at implementation time, with the literal strings snapshot-tested.
- **B16** Node packages build with `tsc` (no bundler); only the Worker entry is bundled (by wrangler/esbuild).
- **B17** All tests use fixture providers/engines from `@seolite/mcp/testkit`; no live network anywhere in this aspect's suite (I9/I10). Real-provider smoke happens at the M2 integration gate (CLI smoke against a local fixture HTTP server, MCP inspector smoke) — owned there.
- **B18** Unhandled internal errors map to exit 2 with a stable code (`INTERNAL`) and a truncated message; no stack traces to stdout in JSON mode.
- **B19** The Worker caches nothing across requests in v1: `ProviderDeps.cache` is wired to an always-miss CacheStore instance constructed per request; provider-level caching is the providers aspect's concern and must be race-safe or absent. Worker provider selection = the five Worker-appropriate providers (tranco unselected — E6).
- **B20** npm packaging correctness for `@seolite/cli`/`@seolite/mcp` (bin, files, exports map, engines) is in scope here; the actual publish action belongs to M2/ci-deploy.
- **B21** Branch/dependency sequencing: `packages/mcp` depends on `@seolite/core` + `@modelcontextprotocol/sdk` + `zod` from Phase 4; the `@seolite/providers` dependency and the real `createWorkerSafeProviders` wiring (`worker/providers.ts`) land in the Phase 6 rebase commit (core-only branch rule, ARCHITECTURE M1). Phase 5 worker tests run against the fixture composition pre-rebase; the identical suite re-runs green post-rebase with the real-outbound allowlist assertions active.
